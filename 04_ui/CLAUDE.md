# 04_ui — Streamlit 화면 구현

## Goal
`lab_app/app.py`와 화면 폴더에 한국어 Streamlit UI를 구현하고, 실제 앱을 실행해 동작을 확인한다.
- 좌측 사이드바 내비게이션
- 화면: 대시보드 / 오늘의 수업 / 코드 실습 / 오답 노트 / 학습 기록
- 넉넉한 코드 에디터(문법 하이라이팅), 실행·채점 버튼, stdout·오류 표시, 단계별 힌트, 정답 확인
- 깔끔한 교육 플랫폼 스타일, 라이트/다크 모드, 불필요한 애니메이션 최소화

## Process
1. (2026-10-16) **코드 에디터 선택**: `streamlit-code-editor` 0.1.22 (Ace 기반, 2024-12 배포)
   - 후보 `streamlit-ace`는 2021년 이후 업데이트가 없다. `streamlit-monaco`는 기능이 적다.
   - wheel의 프런트엔드 번들을 확인했다. `response_mode=["blur", "debounce"]`를 지원하므로 별도 "적용" 버튼 없이 에디터 내용이 앱으로 전달된다. 실제 브라우저에서도 입력 직후 바로 "채점"을 눌렀을 때 최신 코드로 채점되는 것을 확인했다.
   - `.venv`에 설치하고 `requirements.txt`에 추가했다.
2. Streamlit 1.66 API(`st.navigation`, `width="stretch"`, `st.metric(border=)` 등)의 시그니처를 확인한 뒤 작성했다. 1.66에서 폐기 예정인 `use_container_width`는 쓰지 않았다.
3. 구현
   - `app.py`: 경로 설정, **localhost 접속 검사**, `st.navigation`(학습/기록 2개 그룹), 사이드바 요약(연속 학습·진행률)
   - `components.py`: 서비스 캐시(`st.cache_resource`), 콘텐츠 오류 화면, 코드 에디터 래퍼, 실행/채점 결과 표시, **문제 풀이 패널**(실행·채점·힌트·처음 코드로·정답 보기 확인 단계), 개념 블록(예제 실행 버튼), 퀴즈
   - `views/dashboard.py`: 오늘의 수업 카드, 지표 4개, 단계별 진행 막대, Day 카드, 취약 개념, 복습 추천
   - `views/lesson.py`: Day 선택, 5단계 라디오(이동 시 DB에 저장해 이어하기에 사용), 이전/다음 버튼, 완료 조건 안내
   - `views/practice.py`: 열린 Day의 문제 선택, 제출 기록, **자유 실습(채점 없음)**
   - `views/wrong_notes.py`: 미해결/해결 탭, 틀린 코드, 오류 유형별 팁, 메모, 다시 풀기, 오류 유형 통계 차트
   - `views/history.py`: 이어하기, 정답률, 일자별 이력(차트+표), 개념별 성취도(진행 막대), 수업별 진행
4. **실제 앱 실행 및 브라우저 검증**. 검증용 임시 DB(`LAB_DB_PATH`, 세션 임시 폴더)를 써서 실제 `lab_app/data/`에는 기록을 남기지 않았다.
   - Day 1 전체 흐름 확인
     - 빈칸 문제 입력 → 채점 통과
     - 코드 작성 문제: 시작 코드 제출 → 오답 → 힌트 1 → 정답 보기(확인 단계) → 정답 입력 → 통과
     - 문제를 다 풀어도 퀴즈 전에는 미완료 → 정리 퀴즈 제출 → **완료**, Day 2 열림
   - 오답 노트(해결됨으로 이동), 학습 기록(정답률 67%, 일자별 차트), 코드 실습(초안 코드 유지)
   - 서버를 다시 시작한 뒤에도 진도 유지(오늘의 수업 = Day 2, 마지막 단계 위치 복원)
   - 자유 실습: `input()` 입력값 전달, 들여쓰기 오류 표시, 무한 루프 → 5.3초 후 "시간 초과", 앱 정상 동작
   - 다크 모드·라이트 모드 모두 확인. 에디터 테마도 앱 테마를 따라간다.
5. **검증 중 발견해 수정한 문제**
   | # | 문제 | 수정 |
   |---|---|---|
   | 1 | **보안**: Streamlit이 기본으로 모든 네트워크 주소(LAN·외부 IP)에서 접속을 받는다. 코드 실행 앱이라 같은 네트워크의 다른 사람이 이 PC에서 코드를 실행할 수 있다. | `run_app.cmd`가 `--server.address localhost`로 실행한다. `app.py`는 주소가 localhost가 아니면 화면을 막고 안내만 표시한다(직접 확인함). |
   | 2 | 처음 시작한 서버에서 `/lesson` 같은 주소로 바로 접속하면 Streamlit이 `pages/` 폴더를 옛 방식으로 자동 인식했다. 그 결과 `app.py`(메뉴·보안 검사)를 건너뛰었다. | 사용자 확인 후 `lab_app/pages/` → `lab_app/views/`로 이름을 바꿨다. 설계 문서도 수정했다. 재시작 후 직접 주소 접속 정상. |
   | 3 | 한국어 굵게 표시 `**문자열(str)**입니다`가 `**`가 그대로 보였다(CommonMark 규칙: 닫는 `**` 앞이 괄호이고 뒤가 글자). | `content.py`에 **Markdown 강조 검사**를 추가했다(경고). Day 1 퀴즈 해설을 수정했다. 현재 콘텐츠 경고 0건. |
   | 4 | 퀴즈 오답 안내 한 줄에 정답·해설이 섞여 읽기 어려웠다. `<class 'str'>` 같은 답이 굵게 표시되지 않았다. | 결과 / 정답 / 해설을 줄로 나눠 표시하도록 바꿨다. |
   | 5 | 숨김 테스트가 없는 문제에 "숨김 0/0"이 표시됐다. | 숨김 테스트가 있을 때만 표시한다. |
   | 6 | 무한 루프로 시간 초과가 나면 그 전에 출력한 내용까지 사라져 원인을 찾기 어려웠다. | 자유 실행에서는 harness가 출력을 줄 단위로 파일에도 기록한다. 시간 초과 시 그때까지의 출력을 보여 준다(테스트 추가). Windows 줄바꿈(`\r\n`) 변환 문제도 함께 수정했다. |
6. `run_app.cmd` 실행 파일을 작성했다(루트). UTF-8(`chcp 65001`), localhost 전용, 사용 통계 전송 끔, 4초 뒤 브라우저 자동 열기.
7. 전체 테스트 `pytest` → **107 passed** (신규: 시간 초과 시 부분 출력 유지).

## Issues & open questions
- **UI 자동 테스트 없음**: 화면은 수동(브라우저) 검증만 했다. 05단계에서 `streamlit.testing`(AppTest)으로 화면 스모크 테스트를 추가할지 검토한다.
- 에디터는 키 입력을 빠르게 넣으면 `while True:` 다음 줄을 자동 들여쓰기하지 않는 경우가 있었다(자동 입력 도구의 영향일 가능성). 직접 타이핑할 때 동작은 06단계에서 다시 확인한다.
- 퀴즈 라디오 버튼의 접근성 이름이 선택지 텍스트가 아니라 번호(0, 1, …)로 노출된다(Streamlit 동작). 화면 표시에는 문제없다.
- 실행 시 콘솔의 404 오류 2건은 Streamlit이 하위 경로에서 상태 확인을 시도해 생기는 것으로, 동작에 영향이 없다.
- 취약 개념 복습 추천은 그 개념이 수업 `concepts`에 처음 나오는 Day를 가리킨다. 예를 들어 `operator`는 Day 1 문제에도 나오지만 추천은 Day 2다.
- `.streamlit/config.toml`(폴더 필요)은 만들지 않았다. 설정은 `run_app.cmd`의 실행 옵션으로 넣었다.
