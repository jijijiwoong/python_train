3. 처음 요구사항이 모두 테스트로 지켜지는지

요구사항지키는 방법
내 코드를 앱 안에서 직접 실행하지 않기앱 코드 전체를 읽어서 exec·eval 사용이 없는지 검사
무한 루프·출력 폭주에도 앱이 멈추지 않기실제로 무한 루프·폭주 코드를 실행해 강제 종료 확인
정답을 처음부터 보여 주지 않기제출 전에는 정답이 잠겨 있는지 화면·서비스 양쪽에서 확인
문제를 안 풀면 수업 완료 안 됨시작 코드 제출, 예시만 맞춤, 퀴즈만 제출 등 여러 경우를 확인
앱을 껐다 켜도 기록 유지저장소를 새로 연결해도 진도·코드·제출 기록이 남는지 확인
나중에 AI 연결이 쉬운 구조AI 리뷰어 자리에 가짜 리뷰어를 끼워 넣어 동작 확인
화면과 로직 분리화면 코드가 데이터베이스를 직접 쓰지 않는지 검사

요구사항별 테스트 이름까지 정리한 표는 작업 기록에 있습니다.

4. 확인이 필요한 점

자동으로 못 하는 부분: 코드 입력 칸에 글자를 치는 동작, 색상 테마의 모양, 브라우저 자동 열기는 사람이 확인해야 합니다. 04단계에서 확인했고 06단계에서 한 번 더 봅니다.
89%의 의미: 실행되지 않은 코드는 대부분 드문 오류 안내 문구입니다. 코드 실행 도구(harness)는 별도 프로그램에서 돌아서 숫자에는 0%로 잡히지만, 24개 테스트가 간접적으로 확인합니다.
